# MCP Server

The FresherFlow MCP (Model Context Protocol) server lets AI clients call FresherFlow tools for finding jobs, submitting opportunities, and managing listings.

**MCP Server URL:** `https://mcp.fresherflow.in/mcp`

## Quick Start

1. **Connect your AI client** to `https://mcp.fresherflow.in/mcp`
2. **Complete OAuth login** when prompted (or use an API key for headless)
3. **Call tools** based on your role

## Available Tools

| Tool | Public | User | Moderator | Description |
|------|--------|------|-----------|-------------|
| `whoami` | ✅ | ✅ | ✅ | Current connection identity, role, capabilities |
| `get_jobs` | ✅ | ✅ | ✅ | Search live job listings by keyword, city, company, type |
| `submit_opportunity` | ❌ | ✅ | ✅ | Submit a job (DRAFT for users, PUBLISHED for moderators) |
| `list_my_submissions` | ❌ | ✅ | ✅ | Your submissions with status |
| `withdraw_submission` | ❌ | ✅ | ✅ | Withdraw a PENDING_REVIEW submission |
| `get_listing_schema` | ❌ | ❌ | ✅ | Full field contract for listings |
| `create_listing` | ❌ | ❌ | ✅ | Create full listing (defaults to PUBLISHED) |
| `update_listing` | ❌ | ❌ | ✅ | Full replace of a listing |
| `get_listing` | ❌ | ❌ | ✅ | Read a full listing |
| `review_queue` | ❌ | ❌ | ✅ | Submissions awaiting review |
| `approve_submission` | ❌ | ❌ | ✅ | Publish a submission |
| `reject_submission` | ❌ | ❌ | ✅ | Reject with reason |

## Role-Based Access

| Role | How to Get | What Changes |
|------|------------|--------------|
| `public` | No auth | Only `whoami`, `get_jobs` |
| `user` | Sign in to FresherFlow | Submit drafts, manage own submissions |
| `moderator` | Admin panel: `opportunity.review` + `opportunity.publish` | Publish on submit, full listing CRUD, moderation |

**The tool list a connection sees already reflects its role.** A user never sees moderation tools.

## Authentication

### OAuth 2.1 (Recommended)

The MCP server is an OAuth 2.1 **resource server**; the FresherFlow API is the **authorization server**.

1. Client fetches discovery: `GET https://mcp.fresherflow.in/.well-known/oauth-protected-resource`
2. Client registers via DCR: `POST https://api.fresherflow.in/oauth/register`
3. Client redirects user: `GET https://api.fresherflow.in/oauth/authorize?...`
4. User approves on consent screen
5. Client exchanges code for tokens: `POST https://api.fresherflow.in/oauth/token`
6. All tool calls include `Authorization: Bearer <access_token>`

**PKCE S256 is required.** ChatGPT, Codex, and other clients handle this automatically.

### API Key (Headless / CI)

For environments where OAuth is inconvenient:

1. Create an API key in FresherFlow: **Settings → API Keys**
2. Send `Authorization: Bearer <api_key>` or `x-api-key: <api_key>` with requests

## Connect Your AI Client

### Claude Code

```bash
claude mcp add --transport http --scope user fresherflow https://mcp.fresherflow.in/mcp
```

### Claude Desktop

1. Customize → Connectors → Add custom connector
2. URL: `https://mcp.fresherflow.in/mcp`
3. Approve login

### Cursor

1. Settings → Tools & Integrations → MCP Tools → New MCP Server
2. Add to `mcp.json`:
```json
{
  "mcpServers": {
    "fresherflow": { "url": "https://mcp.fresherflow.in/mcp" }
  }
}
```

### Codex CLI

```bash
codex mcp add fresherflow --url https://mcp.fresherflow.in/mcp
```

### Codex Desktop

Settings → Integrations & MCP → Add your own → `https://mcp.fresherflow.in/mcp`

### ChatGPT (Custom Connector)

1. Settings → Connectors → Add custom connector
2. URL: `https://mcp.fresherflow.in/mcp`
3. Registration: **Dynamic Client Registration (DCR)**
4. Base scopes: `mcp`

## Connection Flow

```
┌─────────────┐     1. GET /.well-known/oauth-protected-resource
│   Client    │◄────────────────────────────────────────────────
└──────┬──────┘
       │ 2. POST /oauth/register (DCR)
       ▼
┌─────────────┐     3. GET /oauth/authorize?... (redirects to login)
│  API (Auth) │◄────────────────────────────────────────────────
└──────┬──────┘
       │ 4. User logs in + approves consent screen
       ▼
┌─────────────┐     5. POST /oauth/token (code → tokens)
│   Client    │◄────────────────────────────────────────────────
└──────┬──────┘
       │ 6. Tools calls with Authorization: Bearer <token>
       ▼
┌─────────────┐
│ MCP Server  │
└─────────────┘
```

## Important Rules

- **Never claim a job is live** unless a tool response says `published: true`
- `submit_opportunity` from a user creates a **DRAFT** — moderator must publish
- `submit_opportunity` from a moderator creates **PUBLISHED** — live immediately
- `update_listing` is a **full replace** — omitted fields are cleared
- Call `get_listing` after `create_listing`/`update_listing` to verify stored fields
- Unknown field names in payloads are **silently dropped** — use `get_listing_schema` first

## Rate Limits

| Endpoint | Limit |
|----------|-------|
| `/mcp` | 60 req/min per IP |
| `submit_opportunity` | 60/hr per account |
| OAuth `/register` | 30/hr per IP |
| OAuth `/token` | 60/15min per IP |
| OAuth `/authorize` | 60/15min per IP |

## Error Codes

| Code | Meaning |
|------|---------|
| `-32700` | Parse error (invalid JSON) |
| `-32000` | Rate limit exceeded |
| `-32001` | Auth required / invalid token |
| `-32603` | Internal server error |

## Troubleshooting

- **401 on first call** → Normal. Client must follow `resource_metadata` URL and complete OAuth
- **Tools not found** → Check role via `whoami`. User ≠ Moderator tools
- **Codex `issuer` error** → Upgrade Codex CLI to ≥0.147.0 or use API key
- **Auth fails** → Disconnect and reconnect the MCP server in your client
