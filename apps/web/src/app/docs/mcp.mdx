# MCP Server

The FresherFlow MCP (Model Context Protocol) server lets AI clients call FresherFlow tools for finding jobs, submitting opportunities, and managing listings.

**MCP Server URL:** `https://mcp.fresherflow.in/mcp`

Public, read-only job discovery is also available at `https://mcp.fresherflow.in/mcp/public` without an account. Every tool that writes, or reads account data, requires sign-in.

## Quick Start

1. **Connect your AI client** to `https://mcp.fresherflow.in/mcp`
2. **Complete OAuth login** when prompted
3. **Call tools** based on your role

## Available Tools

| Tool | User | Moderator | Description |
|------|------|-----------|-------------|
| `whoami` | ✅ | ✅ | Current connection identity, role, capabilities |
| `get_jobs` | ✅ | ✅ | Search live job listings by keyword, city, company, type |
| `get_job` | ✅ | ✅ | Full details for one listing by slug or id |
| `submit_opportunity` | ✅ | ✅ | Submit a job (DRAFT for users, PUBLISHED for moderators) |
| `list_my_submissions` | ✅ | ✅ | Your submissions with status |
| `withdraw_submission` | ✅ | ✅ | Withdraw a PENDING_REVIEW submission |
| `update_listing` | ❌ | ✅ | Full replace of a listing |
| `get_listing` | ❌ | ✅ | Read a full listing |
| `review_queue` | ❌ | ✅ | Submissions awaiting review |
| `approve_submission` | ❌ | ✅ | Publish a submission |
| `reject_submission` | ❌ | ✅ | Reject with reason |

## Role-Based Access

| Role | How to Get | What Changes |
|------|------------|--------------|
| `user` | Sign in to FresherFlow | Submit drafts, manage own submissions |
| `moderator` | Admin panel: `opportunity.review` + `opportunity.publish` | Publish on submit, full listing CRUD, moderation |

**The tool list a connection sees already reflects its role.** A user never sees moderation tools. Nothing is anonymous except the `/mcp/public` read-only endpoint, which exposes only `get_jobs` and `get_job` (published, unexpired listings).

If a moderator was granted after the connector was created, use **Settings → Plugins → your FresherFlow connector → Refresh tools** (or reconnect it). ChatGPT caches the tool list, so `whoami` can show `moderator` while the visible tools are still the old set.

## Skills

The plugin ships workflow playbooks that tell an agent how to use these tools together. The tools expose capability; the skills carry the rules and sequence.

| Skill | What it covers |
|-------|----------------|
| `submit-opportunity` | Go from a link or pasted posting to a complete submission in one tool call: read the source, check duplicates, extract only stated fields, then report DRAFT vs PUBLISHED, `duplicate` and `missingFields` correctly. |
| `job-search` | Search the live feed with accurate filters, read a listing by slug or id, and return canonical links. |
| `review-submissions` | Moderator workflow: `review_queue` → approve, reject with a reason, or fix and publish — exactly one path per submission. |

These are the tracked source under `plugins/fresherflow/skills/<name>/SKILL.md`. `pnpm skills:sync` installs them into `.agents/skills/` for agents working in this repo; `pnpm skills:check` verifies the two stay identical.

## Authentication

### OAuth 2.1

The MCP server is an OAuth 2.1 **resource server**; the FresherFlow API is the **authorization server**. `/mcp` always requires a bearer token — there is no API key. `/mcp/public` is the only unauthenticated endpoint, and it is read-only.

1. Client fetches discovery: `GET https://mcp.fresherflow.in/.well-known/oauth-protected-resource/mcp`
2. Client registers via DCR: `POST https://api.fresherflow.in/oauth/register`
3. Client redirects user: `GET https://api.fresherflow.in/oauth/authorize?...`
4. User approves on consent screen
5. Client exchanges code for tokens: `POST https://api.fresherflow.in/oauth/token`
6. All tool calls include `Authorization: Bearer <access_token>`

**PKCE S256 is required**, and the authorize request must carry the RFC 8707 `resource` parameter for `https://mcp.fresherflow.in/mcp`. ChatGPT, Codex, and other clients handle both automatically. Access tokens last 1 hour; refresh tokens last 90 days.

Manage or revoke connections at any time from **Settings → Connected apps** in the web app.

## Connect Your AI Client

### Claude Code

```bash
claude mcp add --transport http --scope user fresherflow https://mcp.fresherflow.in/mcp
```

### Claude Desktop

1. Customize → Connectors → Add custom connector
2. URL: `https://mcp.fresherflow.in/mcp`
3. Approve login

### Cursor

1. Settings → Tools & Integrations → MCP Tools → New MCP Server
2. Add to `mcp.json`:
```json
{
  "mcpServers": {
    "fresherflow": { "url": "https://mcp.fresherflow.in/mcp" }
  }
}
```

### Codex CLI

```bash
codex mcp add fresherflow --url https://mcp.fresherflow.in/mcp
```

### Codex Desktop

Settings → Integrations & MCP → Add your own → `https://mcp.fresherflow.in/mcp`

### ChatGPT (Custom Connector)

1. Settings → Connectors → Add custom connector
2. URL: `https://mcp.fresherflow.in/mcp`
3. Registration: **Dynamic Client Registration (DCR)**
4. Base scopes: `mcp`

## Connection Flow

```
┌─────────────┐     1. GET /.well-known/oauth-protected-resource/mcp
│   Client    │◄────────────────────────────────────────────────
└──────┬──────┘
       │ 2. POST /oauth/register (DCR)
       ▼
┌─────────────┐     3. GET /oauth/authorize?... (redirects to login)
│  API (Auth) │◄────────────────────────────────────────────────
└──────┬──────┘
       │ 4. User logs in + approves consent screen
       ▼
┌─────────────┐     5. POST /oauth/token (code → tokens)
│   Client    │◄────────────────────────────────────────────────
└──────┬──────┘
       │ 6. Tools calls with Authorization: Bearer <token>
       ▼
┌─────────────┐
│ MCP Server  │
└─────────────┘
```

## Important Rules

- **Never claim a job is live** unless a tool response says `published: true`
- `submit_opportunity` is rejected unless it carries a description of at least 80 characters and a location (or `workMode: REMOTE`); a `walkin` also needs real dates and a real venue
- `submit_opportunity` from a user creates a **DRAFT** — moderator must publish
- `submit_opportunity` from a moderator creates **PUBLISHED** — live immediately
- `update_listing` is a **full replace** — omitted fields are cleared
- Call `get_listing` after `update_listing` to verify stored fields
- Each write tool carries its own field contract: there is no separate schema, template or rules tool to call first
- `submit_opportunity` rejects unknown field names, so a typo is an error rather than a silently missing value
- `update_listing` payloads are still a closed object at the API — use only the field names listed in its description

## Rate Limits

| Endpoint | Limit |
|----------|-------|
| `/mcp` (Worker guard) | 600 req/min per IP |
| identity, own-submission reads and withdraw | 180/min per account |
| `submit_opportunity` | 60/hr per account |
| listing writes | 60/min per account |
| listing reads | 120/min per account |
| moderation actions | 30/min per account |
| OAuth `/register` | 30/hr per IP |
| OAuth `/token` | 60/15min per IP |
| OAuth `/authorize` | 60/15min per IP |

## Error Codes

| Code | Meaning |
|------|---------|
| `-32700` | Parse error (invalid JSON) |
| `-32000` | Rate limit exceeded |
| `-32001` | Auth required / invalid token |
| `-32603` | Internal server error |

## Troubleshooting

- **401 on first call** → Normal. Client must follow `resource_metadata` URL and complete OAuth
- **Tools not found** → Check role via `whoami`. User ≠ Moderator tools
- **Codex `issuer` error** → Upgrade Codex CLI to ≥0.147.0
- **Auth fails** → Disconnect and reconnect the MCP server in your client
- **Expired token** → Clients refresh automatically; if it still fails, reconnect FresherFlow from **Settings → Connected apps**
