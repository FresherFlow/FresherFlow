# FresherFlow

FresherFlow is a job and walk-in opportunity platform for freshers in India. It collects postings from external sources, normalizes them into one listing contract, serves them through a public feed, and lets candidates search, save and apply — from the web, the mobile app, or an AI client over MCP.

<DocCallout variant="note" title="One listing contract">
  The admin form, the ingestion pipeline and the MCP server all write listings through the same `opportunitySchema`. Unknown keys are dropped rather than rejected, so field names must be exact.
</DocCallout>

## What the platform does

- **Collects** postings through the job-discovery and job-processor scripts.
- **Normalizes** them into a single listing shape shared by every write path.
- **Publishes** through a versioned feed on Cloudflare R2, served over the CDN.
- **Serves** public job pages, dashboards and the mobile app.
- **Exposes** the same data as MCP tools, with role-filtered tool lists.

## The apps

- **Web** — public feed, company pages, accounts and admin UI. Next.js App Router and Tailwind CSS.
- **API** — REST surface, auth, validation and business rules. Node.js, Express, Zod and Prisma.
- **MCP** — AI-client surface. A Cloudflare Worker over the API with OAuth 2.1.
- **Mobile** — candidate app with an offline feed cache. Expo, React Native and MMKV.
- **Worker** — BullMQ processors for background work.

Frontend apps never import Prisma. They call the API through `packages/api-client`.

## How a posting reaches a candidate

1. **Discover** — scripts find postings on external sources and record raw jobs.
2. **Parse** — `packages/parser` extracts structured fields from the raw text.
3. **Validate** — `opportunitySchema` is the single listing contract.
4. **Review** — community submissions become drafts until a moderator publishes them.
5. **Publish** — the publish flow regenerates the feed and invalidates the affected tags.
6. **Serve** — a versioned feed object on R2 is served to web, mobile and the MCP public tools.

Feed regeneration always starts from an admin or publish flow, never from a public route.

## Shared packages

- `@fresherflow/types` — shared request and response types.
- `@fresherflow/utils` — pure helpers for eligibility, opportunity rules and locations.
- `@fresherflow/api-client` — frontend API wrappers.
- `@fresherflow/parser` — extraction and normalization.
- `@fresherflow/database` — Prisma and Redis clients. Server-only.
- `@fresherflow/queue` — BullMQ queue contracts. Server-only.
- `@fresherflow/ui` — shared UI primitives.

There is no `packages/domain`. Business rules live in API services or pure helpers in `packages/utils` and `packages/types`.

## Local development

```bash
pnpm install --frozen-lockfile
pnpm db:generate
pnpm turbo typecheck --filter=fresherflow-api --filter=fresherflow-web
pnpm turbo build --filter=fresherflow-api --filter=fresherflow-web
pnpm --filter fresherflow-api test
```

`postinstall` deliberately skips Prisma generation. After any change to `schema.prisma`, run `pnpm db:generate` yourself or typecheck will fail on stale types.
