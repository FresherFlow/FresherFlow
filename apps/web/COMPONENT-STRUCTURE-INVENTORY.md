## 2. How many are different / weird

### A. Two component homes coexist (the core violation)
- `src/features/*/components` — 15 dirs, e.g. `jobs/components` = 63 files (recursive), `admin/components` = 10, `profile/components` = 14.
- `src/app/**/_components` — 11 dirs:
  - `(admin)/admin/dashboard/_components` (2 files), `admin/login/_components` (4), `admin/users/_components` (4)
  - `(auth)/_components` (1), `(auth)/choose-username/_components` (1), `(auth)/login/_components` (1), `(auth)/logout/_components` (1), `(auth)/onboarding/_components` (1)
  - `(public)/community/[id]/_components` (`PostDetailClient.tsx` — live, imported by its route page), `(public)/companies/[slug]/_components` (`CompanyRoleCard.tsx` — live, imported by its route page)
  - `dev/dashboard-01/_components` (1)
- Jobs pages (`src/app/(public)/jobs/page.tsx`, `[slug]/page.tsx`) import straight from `@/features/jobs/components/JobsPageClient` — no `_components` indirection. Auth/admin/community/companies routes DO use `_components`. Same app, two conventions.

### B. Third component home: `src/ui/` + `src/features/admin/ui/`
- `src/ui/` = 53 `.tsx` + `data-grid/`, `data-table/` subfolders. Generic primitives per AGENTS.md.
- `src/features/admin/ui/` = 4 files (`InlineEditableField, SmartInput, SmartSelect, SmartTextarea`). Only feature with its own `ui/` folder. Every other feature uses `components/`. Why is admin special?

### C. Casing duplicates in `src/ui/` (AGENTS.md calls this a bug explicitly)
- `DropdownMenu.tsx` + `dropdown-menu.tsx` coexist.
- Mixed `PascalCase` (`Button, Card, Dialog, Input`) vs `kebab-case` (`avatar, label, drawer, toggle, site-header, section-cards, app-sidebar, nav-main`) in the SAME folder. Convention table says components = `PascalCase.tsx`, folders = `kebab-case` — `src/ui` violates its own table.

### D. One-off folder types: `tabs/`
- Only 2 features have `tabs/`: `features/jobs/tabs` (7 files: AlertsTab, AppliedTab, ForYouTab, SavedTab, SearchesTab, NotificationsTab, NewSearchDialog) and `features/settings/tabs`.
- AGENTS.md allows `components, hooks, api, domain, utils` for large features. `tabs/` is not in the list — it's `components/` by another name.

### E. Nesting weirdness
- `features/admin/opportunities/components/OpportunityForm/components/` — components-inside-components (4 levels).
- `features/jobs/components/` mixes flat files (30: `JobFilterBar, JobsFilterBar, CategoryPage, WalkinEventBoard…`) with subfolders (`detail/, discussion/, post/, JobCard/, WalkinMap/`). Note `JobFilterBar` vs `JobsFilterBar` — near-duplicate names, same folder.
- `JobCard/` (PascalCase) sits beside `detail/` (lowercase) — folder-casing inconsistency inside one `components/` dir.

### F. Hooks / utils / api / domain scattered (same "pick 1" disease, other file types)
- `hooks`: 8 homes — `src/hooks/` (11 generic files) + `features/{admin, admin/opportunities, companies, dashboard, jobs, notifications, profile}/hooks|components`. AGENTS.md says generic-only in `src/hooks`, feature hooks beside feature — but both exist for the same concept.
- `utils`: 3 homes — `src/lib/utils/` (8 files) + `features/jobs/utils` (13 files) + `features/companies/utils`.
- `api`: 4 homes — `src/app/api/` (routes) + `src/lib/api/` (infra) + `features/{jobs, contribute, resources}/api/`.
- `domain/`: only `features/jobs/domain/` (`display/, taxonomy/, eligibility, matchScore, timeline…`). No other feature has one — either jobs is over-split or everyone else is under-split.

### G. Doc-vs-code name mismatch
- `AGENTS.md` ownership test says: "Job functionality → `features/opportunities/` (jobs, walk-ins, internships are one feature: opportunities)". Code has `features/jobs/` (63+ component files, `domain/taxonomy`, `tabs/`). Key-files table also cites `src/features/opportunities/` and `src/features/navigation/` — neither directory exists on disk. The doc describes the target; the tree is the present.

### H. ~~Dead / empty folders~~ (corrected 2026-10-10: an early count without `-LiteralPath` misreported these as empty — bracket paths globbed to nothing. Both hold live route-private components, verified by importers + typecheck.)
- `(public)/community/[id]/_components/PostDetailClient.tsx` — live, imported by `./page.tsx`. KEEP.
